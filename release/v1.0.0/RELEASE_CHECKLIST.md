## B. Before creating the stable tag `v1.0.0` (local)
- [ ] Owner confirms the licence variant (CERN-OHL-S-2.0 prepared; W or P are the alternatives).
- [ ] Owner reviews the renders and silkscreen in `docs/visual-review/VISUAL_REVIEW.md`.
- [ ] Then: `git tag -a v1.0.0 -m "v1.0.0: fabrication-ready open hardware design release (Rev A), NOT physically tested"`
      on the release commit. A candidate tag `v1.0.0-rc1` marks the same content until then.

## C. Manual GitHub publication (owner only; nothing was pushed by the AI session)
1. Create or choose the GitHub repository; check that it is the intended visibility (public).
2. Merge `release/v0.3.0-finalization` into `main` locally (fast-forward from the V0.2.0 history).
3. `git push origin main` and `git push origin v1.0.0`.
4. On GitHub, create a release from tag `v1.0.0`. Paste `RELEASE_NOTES_V1.0.0.md`, attach the three ZIPs and
   `SHA256SUMS.txt`, and mark it as **not** "pre-release" only if you accept the "not physically tested" status.
5. Check that the README renders: images, Mermaid diagrams, links.

## D. After the first physical build (future milestone)
- [ ] Run tests T1–T15 and record the evidence in `testing/`.
- [ ] Update `PHYSICAL_VALIDATION_STATUS.md` and release v1.0.1/v1.1.0 or Rev B as needed.
